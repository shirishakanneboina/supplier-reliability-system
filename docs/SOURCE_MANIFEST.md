# Supplier Reliability System – Source Manifest

## 1. Project Information

**Project Name:** Supplier Reliability Scoring and Data Generation System

**Project Type:** Python-based synthetic data generation, supplier scoring, validation, and dashboard application.

**Data Source:** Synthetic data generated using Python scripts.

**Random Seed:** 20261030

All records are synthetic and created for project evaluation. No real supplier records or confidential business information are used.

## 2. Data Generation Sources

The system generates the following 11 datasets:

| Dataset | Generated Records | Description |
|---|---:|---|
| suppliers | 1,000 | Supplier master information |
| sites | 1,976 | Supplier operating locations |
| contracts | 2,016 | Supplier contract records |
| purchase_orders | 10,000 | Purchase order records |
| po_lines | 20,011 | Purchase order line items |
| shipments | 15,000 | Shipment records |
| delivery_events | 32,899 | Shipment tracking events |
| inspections | 20,000 | Quality inspection records |
| invoices | 10,000 | Invoice and payment records |
| risk_signals | 1,514 | Supplier risk observations |
| supplier_scores | 1,000 | Calculated supplier reliability scores |

## 3. Generation Process

The datasets are generated through Python modules in the `src/` directory.

The generation process follows the dependency order:

1. Suppliers
2. Sites
3. Contracts
4. Purchase Orders
5. PO Lines
6. Shipments
7. Delivery Events
8. Inspections
9. Invoices
10. Risk Signals
11. Supplier Scores

Parent records are generated before dependent records to maintain relational consistency.

## 4. Output Locations

Generated data is maintained in the following project directories:

| Location | Purpose |
|---|---|
| `data/raw/` | Generated raw CSV datasets |
| `data/exports/` | JSON exports, validation reports, anomaly cases, and ground truth |
| SQLite database file | Relational storage of generated datasets |

The SQL export is also generated by the project for database portability.

## 5. Data Quality and Validation Sources

The validation process is implemented in:

`src/validation.py`

The validation process includes:

- Primary-key uniqueness checks.
- Foreign-key integrity checks.
- Inspection quantity validation.
- Defect-rate calculation validation.
- Purchase order line arithmetic checks.
- Supplier score range and missing-value checks.
- Risk signal source and date checks.

**Latest recorded validation result:**

- Total checks: 30
- Passed: 30
- Failed: 0

Validation output files:

- `data/exports/validation_details.csv`
- `data/exports/validation_summary.csv`

## 6. Anomaly Testing Sources

Anomaly test generation is implemented in:

`src/anomaly_generator.py`

The project includes five isolated anomaly scenarios:

1. Missing purchase order reference.
2. Delivery event before shipment dispatch.
3. Future information used in supplier scoring.
4. Risk signal without source and date.
5. Supplier-site association inconsistency.

Output files:

- `data/exports/anomaly_cases.csv`
- `data/exports/ground_truth.csv`

The anomaly cases are kept separate from the normal baseline datasets.

## 7. Reproducibility Source

Reproducibility testing is implemented in:

`src/reproducibility_check.py`

The script runs the data generation process twice and compares hashes of the generated raw CSV datasets.

The completed test confirmed that all 11 raw CSV datasets matched across the two runs.

This result applies to the raw CSV files checked by the reproducibility script.

## 8. Database and Dashboard Sources

**Database:** SQLite

The generated datasets are stored in relational tables with primary-key and foreign-key relationships.

**Dashboard:** Streamlit

The dashboard provides:

- Executive Overview
- Supplier Explorer
- Anomaly Monitoring
- Data Records

The dashboard presents supplier performance metrics, supplier-level information, anomaly cases, and generated data records.

## 9. Provenance and Limitations

- All data is synthetically generated.
- No external supplier dataset or confidential business data is used.
- The random seed is maintained in the generation source code.
- Generated distributions are intended for demonstration and evaluation.
- Validation results represent the checks implemented in the validation script.
- Reproducibility results cover the 11 raw CSV datasets checked by the reproducibility script.

## 10. Execution

Run the main data generation script from the project root:

```bash
python src/main.py
```

Run validation:

```bash
python src/validation.py
```

Run reproducibility testing:

```bash
python src/reproducibility_check.py
```
