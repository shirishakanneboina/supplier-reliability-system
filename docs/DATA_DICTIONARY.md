# Supplier Reliability System – Data Dictionary

## 1. Overview

This document describes the structure, data types, relationships, business rules, and validation requirements for the 11 datasets generated by the Supplier Reliability System.

All datasets contain synthetic data generated for project evaluation. No real supplier or confidential business records are used.

## 2. Entity Summary

| Entity | Records | Description |
|---|---:|---|
| Suppliers | 1,000 | Supplier master information |
| Sites | 1,976 | Supplier operating locations |
| Contracts | 2,016 | Supplier contract information |
| Purchase Orders | 10,000 | Orders placed with suppliers |
| PO Lines | 20,011 | Individual products and quantities in orders |
| Shipments | 15,000 | Shipment records linked to purchase orders |
| Delivery Events | 32,899 | Shipment tracking events |
| Inspections | 20,000 | Quality inspection results |
| Invoices | 10,000 | Supplier invoice information |
| Risk Signals | 1,514 | Supplier risk observations |
| Supplier Scores | 1,000 | Calculated supplier reliability scores |

## 3. Data Types and Conventions

- `str`: Text or identifier.
- `int64`: Whole number.
- `float64`: Decimal number.
- Date fields are stored as text and use the generated date or timestamp representation.
- Scores use a 0–100 scale.
- Defect rates are expressed as percentages from 0–100.
- Required fields must not be null or empty.
- Primary keys must be unique.
- Foreign keys must reference existing parent records in the normal baseline datasets.
- Conditional fields may be missing when the corresponding performance information is unavailable.
- Actual identifier formats and enumerated values are defined by the project generators.

## 4. Entity Data Dictionaries

### 4.1 Suppliers

**Purpose:** Stores the master information of each supplier.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| supplier_id | str | Yes | Primary key; unique supplier identifier |
| supplier_name | str | Yes | Supplier name; non-empty |
| country | str | Yes | Country name; non-empty |
| capacity_units_per_month | int64 | Yes | Monthly capacity; must be greater than zero |

### 4.2 Sites

**Purpose:** Stores operating locations associated with suppliers.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| site_id | str | Yes | Primary key; unique site identifier |
| supplier_id | str | Yes | Foreign key referencing Suppliers |
| city | str | Yes | Site city; non-empty |
| site_type | str | Yes | Site classification; values follow the site generator |

| Field | Type | Required | Validation / Description |

### 4.4 Purchase Orders

**Purpose:** Stores orders placed with suppliers under contracts.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| purchase_order_id | str | Yes | Primary key; unique PO identifier |
| supplier_id | str | Yes | Foreign key referencing Suppliers |
| contract_id | str | Yes | Foreign key referencing Contracts |
| order_date | str | Yes | Purchase order creation date |
| expected_delivery_date | str | Yes | Expected delivery date; must not precede order date |
| total_amount | int64 | Yes | Total purchase order amount; non-negative |
| status | str | Yes | Order lifecycle status; values follow the purchase order generator |

### 4.5 PO Lines

**Purpose:** Stores individual products and quantities belonging to purchase orders.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| po_line_id | str | Yes | Primary key; unique PO line identifier |
| purchase_order_id | str | Yes | Foreign key referencing Purchase Orders |
| product_name | str | Yes | Product description |
| quantity | int64 | Yes | Ordered quantity; greater than zero |
| unit_price | int64 | Yes | Price per unit; non-negative |
| line_total | int64 | Yes | Must equal quantity multiplied by unit price |

**Business rules:**
- Each PO line must reference an existing purchase order.
- Line total must equal quantity multiplied by unit price.
- The sum of PO line totals should reconcile with the corresponding purchase order total.

### 4.6 Shipments

**Purpose:** Stores shipment information associated with purchase orders.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| shipment_id | str | Yes | Primary key; unique shipment identifier |
| purchase_order_id | str | Yes | Foreign key referencing Purchase Orders |
| supplier_id | str | Yes | Foreign key referencing Suppliers |
| shipment_date | str | Yes | Shipment dispatch date |
| expected_delivery_date | str | Yes | Expected delivery date |
| carrier | str | Yes | Carrier or logistics provider |
| tracking_number | str | Yes | Shipment tracking identifier |
| status | str | Yes | Shipment lifecycle status; values follow the shipment generator |

**Business rule:** The shipment supplier should match the supplier associated with its purchase order.

### 4.7 Delivery Events

**Purpose:** Tracks shipment movement and delivery progress.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| delivery_event_id | str | Yes | Primary key; unique event identifier |
| shipment_id | str | Yes | Foreign key referencing Shipments |
| event_type | str | Yes | Event classification; values follow the delivery event generator |
| event_date | str | Yes | Date or timestamp of the event |
| location | str | Yes | Event location |
| remarks | str | Yes | Event description or remarks |

**Business rules:**
- Each delivery event must reference an existing shipment.
- Events should follow a valid shipment lifecycle.
- A delivery event must not occur before dispatch in valid baseline records.

### 4.8 Inspections

**Purpose:** Stores quality inspection measurements and results.

| Field | Type | Required | Validation / Description |
|---|---|---|---|
| inspection_id | str | Yes | Primary key; unique inspection identifier |
| shipment_id | str | Yes | Foreign key referencing Shipments |
| supplier_id | str | Yes | Foreign key referencing Suppliers |
| inspection_date | str | Yes | Inspection date |
| inspection_type | str | Yes | Inspection classification |
| inspected_quantity | int64 | Yes | Quantity inspected; greater than zero |
| defective_quantity | int64 | Yes | Defective quantity; between zero and inspected quantity |
| defect_rate | float64 | Yes | Defective quantity divided by inspected quantity, multiplied by 100; percentage from 0–100 |
| quality_status | str | Yes | Quality result based on defect rate |

**Business rules:**
- Defective quantity must not exceed inspected quantity.
- Defect rate must equal `(defective_quantity / inspected_quantity) × 100`.
- The supplier associated with an inspection must match the supplier of the inspected shipment.

### 4.9 Invoices

| Field | Type | Required | Validation / Description |

| supplier_id | str | Yes | Foreign key referencing Suppliers |
| invoice_date | str | Yes | Invoice issue date |
| invoice_amount | float64 | Yes | Invoice monetary amount; non-negative |
| payment_status | str | Yes | Payment lifecycle status; values follow the invoice generator |

**Business rule:** The supplier associated with an invoice should match the supplier of its purchase order.
